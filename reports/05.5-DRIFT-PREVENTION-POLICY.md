# NEXO 05.5 — DRIFT PREVENTION POLICY

Diagnóstico (verificado en 05.3/05.4): el drift producción-vs-HEAD fue causado por deploy desde un working tree sin commits (Cloudflare registraba `version_upload` sin author). La mitigación robusta es bloquear el anti-pattern por pre-deploy checks, no solamente documentar best practices.

## 1. Prohibiciones (policy)

- Deploy solo desde commits pushados (`git rev-parse @{u} == HEAD`).
- Prohibido `wrangler deploy` con `git status --porcelain` no-vacío (salvo emergencia documentada por escrito).
- CI/validator compara el commit declarado para deploy con el commit en remoto.

## 2. Enforcement sugiido (docs solamente; no se introdujeron hooks al repo)

```sh
assert [ -z "$(git status --porcelain)" ] || { echo "dirty tree: deploy aborted"; exit 1; }
sha_local=$(git rev-parse HEAD)
sha_remote=$(git rev-parse @{u})
[ "$sha_local" = "$sha_remote" ] || { echo "local HEAD ≠ remote HEAD: deploy aborted"; exit 2; }
npx wrangler deploy
```

## 3. Rama recovery prohibida para producción

La rama `recovery/nexo-production-2026-08-22` existe sólo con fines preservativos (artefactos de recuperación). NO se hará deploy desde esa rama ni se hará merge-us de ella en producción. Su merge condicional dependerá de una fase autorizada posterior a reconciliación scope-completo.

## 4. Postura oficial por approval (fase future autorizada)

- `main` como trunk con protection de ramas y pre-push hook opcional.
- Deployment por release-tag o workflow intemanual que valide el upstream.
